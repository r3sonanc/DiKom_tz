## Описание

Две карты склада, от одного до пяти роботов, совместное планирование маршрутов,
ручное управление и проверка отказов. Симулятор и диспетчер работают в отдельных
процессах и обмениваются командами и состояниями через ROS2 Jazzy.
Веб-интерфейс написан на обычных HTML, CSS и JavaScript.

## Запуск

Потребуется установленный и запущенный Docker:

- Ubuntu 24.04: Docker Engine и Docker Compose v2.
- Windows: Docker Desktop в режиме Linux containers.

Python, ROS2 и зависимости устанавливаются внутри образа. На компьютере
дополнительно устанавливать их не нужно. Для первой сборки нужен интернет.

Из папки проекта выполните в PowerShell или терминале Ubuntu:

```sh
docker compose up --build -d
```

Откройте **http://localhost:8000**. Начальная сцена — обычный склад с тремя
роботами на парковках. После первой сборки достаточно `docker compose up -d`.

Состояние контейнера и журнал:

```sh
docker compose ps
docker compose logs -f warehouse
```

Остановка:

```sh
docker compose down
```

Состояние сцены хранится в памяти: после перезапуска создаётся новая симуляция.
Порт 8000 должен быть свободен.

## Управление

1. Выберите робота, затем узел на карте или в списке и нажмите «Отправить».
2. «На парковку» назначает свободную парковку.
3. «Остановить» ставит весь парк на паузу; «Возобновить» продолжает работу.
4. «Тёмный цех» постоянно назначает случайные дальние цели.
5. Для ручного режима включите «Ручное управление» и удерживайте WASD или
   экранные кнопки. W/S — вперёд/назад, A/D — поворот. Остальной парк ждёт.
   Перед выходом вернитесь к навигационному узлу.
6. В «Проверке отказов» доступны застревание, потеря и замедление связи.
   После застревания сначала снимите его имитацию, затем сбросьте ошибку.

Карту и число роботов можно менять в интерфейсе кнопкой «Новая симуляция».
На обычной карте доступны 1–3 робота, на карте «Узкие коридоры» — 1–5.
Для изменения начальной сцены задайте `WAREHOUSE_MAP` (`normal`/`hardcore`)
и `WAREHOUSE_ROBOTS` в окружении перед `docker compose up` либо измените
значения по умолчанию в `compose.yaml`.
`hardcore` — внутреннее имя карты «Узкие коридоры».

## Проверка запуска

У http://localhost:8000/api/health ответ `200` и `"ok": true` означает,
что контроллер работает и получает свежую телеметрию через ROS2.
Состояние мира доступно по `/api/state`, метрики — по `/metrics`.

Проверить реальные ROS-ноды и топики внутри контейнера:

```sh
docker compose exec warehouse bash -lc "source /workspace/install/setup.bash && ros2 node list"
docker compose exec warehouse bash -lc "source /workspace/install/setup.bash && ros2 topic list"
```

Ожидаются ноды `/warehouse_simulator`, `/warehouse_dispatcher` и топики
`/warehouse/commands`, `/warehouse/states`.

## Автотесты

```sh
docker build --target test -t dikom-tests .
docker run --rm dikom-tests
```

Тестовые зависимости устанавливаются только в стадию `test`.
Обычный запуск использует стадию `runtime`.
Прогоны безопасности, замеры до/после и проверка работающего ROS:
[VALIDATION.md](docs/VALIDATION.md).

Код находится в `warehouse/`, интерфейс — в `warehouse/static/`.
`launch/`, `resource/`, `package.xml`, `setup.py` и `setup.cfg` нужны ROS2
для сборки и запуска пакета. `Dockerfile`, `compose.yaml` и `requirements.txt`
описывают воспроизводимый запуск. Окружение `/opt/venv` создаётся только
внутри Docker: оно изолирует Python-зависимости приложения и сохраняет
доступ к установленным в образе ROS-библиотекам.
