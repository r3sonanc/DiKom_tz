# DiKom · симуляция склада

Решение тестового задания: два склада из ТЗ, физический 2D-симулятор дифференциальных роботов в **ROS2 Jazzy**, диспетчер нескольких роботов и веб-интерфейс на русском. Целевая среда — **Ubuntu 24.04 / Python 3.12**. Исходные условия сохранены в `тестовое задание.md` и `доп. инфа.md`.

## Запуск одной командой

Установите Docker Engine и Docker Compose v2, затем из папки проекта:

```bash
docker compose up --build
```

Откройте **http://localhost:8000**. Первая сборка скачивает ROS и Python-зависимости. После запуска доступны карта, три робота на парковках, команды и переключение сценариев. В контейнере работают **два отдельных ROS-процесса**, а физика не зависит от открытого браузера.

Остановка:

```bash
docker compose down
```

Для старта сразу на сложной карте с пятью роботами (Ubuntu):

```bash
WAREHOUSE_MAP=hardcore WAREHOUSE_ROBOTS=5 docker compose up --build
```

На Windows с Docker Desktop команда обычного запуска такая же; карту и число роботов можно поменять в интерфейсе. Порт опубликован на `127.0.0.1`.

## Что попробовать

1. Выберите робота и точку на карте, отправьте его в выбранный узел. Следите за позицией, скоростью, направлением и приказом.
2. Включите «Тёмный цех»: диспетчер выдаёт разные дальние цели. Повторите на сложной карте с пятью роботами.
3. Включите неисправность «Застрял». Узлы и ребро неисправного робота останутся заняты; остальные используют доступные маршруты. Если робот физически перекрыл единственный проход, перейти сквозь него невозможно.
4. Выключите неисправность и сбросьте ошибку. При необходимости нажмите «Возобновить».
5. Проверьте «Потеря связи» и «Троттлинг»: независимый watchdog тормозит робота без продления команды. После восстановления связи продолжается только подтверждённый безопасный маршрут.
6. Включите ручное управление. **W/S** — вперёд/назад, **A/D** — поворот. Остальные роботы остановятся. Отпускание клавиш, потеря фокуса и watchdog останавливают ручное движение. Для возврата к автоматике верните робота к узлу и нажмите «Возобновить»; при ошибке сначала сбросьте её. Стены физически ограничивают движение.

«Стоп» консервативно ставит весь флот на паузу. Это позволяет безопасно сохранить резервирование даже при остановке посреди ребра. При выключении «Тёмного цеха» уже выданные задания завершаются; новые не создаются.

## Проверки

Всё тестирование в той же Ubuntu-среде, где запускается приложение:

```bash
docker compose run --rm --no-deps warehouse bash -lc \
  'cd /workspace/src/warehouse_sim && /opt/venv/bin/python -m pytest -q'

docker compose run --rm --no-deps warehouse bash -lc \
  'cd /workspace/src/warehouse_sim && /opt/venv/bin/python tools/stress.py --seconds 600 --seeds 3'
```

Без ROS можно проверить **чистые ядра**, HTTP и WebSocket (на Windows замените `python3` на `python` и используйте `.venv\Scripts\activate`):

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest -q
ruff check warehouse tests tools launch setup.py
```

Это не альтернативный режим запуска симулятора: рабочий запуск по-прежнему использует ROS2.

Проверить уже запущенное приложение через настоящий ROS-обмен:

```bash
docker compose exec warehouse bash -lc \
  'source /opt/ros/jazzy/setup.bash && cd /workspace/src/warehouse_sim && python tools/live_smoke.py --ros'
```

Сценарий создаёт свои миры, выполняет команды и проверки отказов, затем возвращает обычный склад с тремя роботами. Он занимает около минуты; не запускайте его одновременно с ручной демонстрацией.

## Запуск без Docker на Ubuntu 24.04

Установите ROS2 Jazzy по [официальной инструкции](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html), включая `ros-jazzy-ros-base`, а затем:

```bash
sudo apt install python3-venv python3-colcon-common-extensions
source /opt/ros/jazzy/setup.bash
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m colcon build --merge-install --packages-select warehouse_sim
source install/setup.bash
python -m warehouse.ros_simulator &
SIM_PID=$!
python -m warehouse.api
kill "$SIM_PID"
```

Два модуля также удобно запускать в двух отдельных терминалах с активированными ROS и venv. ROS launch используется контейнером; локально он также доступен после сборки, если Python-зависимости установлены в интерпретатор, которым созданы исполняемые файлы colcon. Модули явно используют активный Python и избегают этой неоднозначности.

## Две версии

В корне находится версия **с комментариями**. Скрипт создаёт две самостоятельные папки и два ZIP для сдачи:

```bash
python tools/package_versions.py
```

- `versions/commented/` и `artifacts/dikom-commented.zip` — исходный код с пояснениями.
- `versions/clean/` и `artifacts/dikom-clean.zip` — тот же исполняемый код без комментариев и Python docstring.

Инструкции и документация присутствуют в обеих версиях. Скрипт проверяет эквивалентность Python AST после удаления документационных строк. Различия относятся к пояснениям, алгоритмы одинаковые.

## Границы решения

Приоритетный Cooperative A* имеет ограниченный бюджет и не является полным MAPF-решателем: для отдельных разрешимых комбинаций целей может потребоваться другой порядок заданий. При отсутствии найденного плана роботы безопасно ждут с объяснением причины. Нельзя гарантировать движение через физически перекрытый единственный проход или взаимный обмен на линии без места для разъезда. Это ограничение отмечено явно, а стандартные сценарии уступания и обхода проверены тестами.

Используются идеи приказов, состояния и разрешённых участков пути из VDA5050. Полная совместимость с VDA5050, MQTT и сертификация не заявляются: ТЗ требует минимальный диспетчер, транспортом здесь служит ROS2.
